------------------------------------------------------------------------
Tool boundaries (each layer owned by exactly one tool):

  PySpark    -> IQR ingestion + data-quality standardization only
  loader.py  -> config-driven validation + landing to Bronze, both sources
  DuckDB     -> local warehouse, default dbt target (no credentials needed)
  Snowflake  -> documented alternate dbt target, same models
  dbt        -> all dimensional modeling (star schema), business logic
                (financial tiers, boarding-time proxy), and testing
  FastAPI    -> read-only presentation over the marts; no model, no /predict
  Power BI   -> presentation only, connects to the marts alone

------------------------------------------------------------------------
Local vs. S3: src/cms_platform/common/settings.py resolves data/raw and
data/standardized to either local paths or s3a:// URIs based on the
CMS_STORAGE_MODE environment variable -- switching environments is a
one-setting change, not a code change. Snowflake's internal named stage
would become an external stage backed by a storage integration pointed at
an S3 curated prefix; nothing in dbt, the API, or Power BI changes.
